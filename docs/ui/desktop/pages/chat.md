# ③ 聊天详情（Chat）— 桌面

> 索引与全局规范见 [../design.md](../design.md)。移动端原页：`docs/ui/mobile/pages/chat.md`
> ——**渲染规则与状态语义全部沿用，本文件只写桌面差异**。

### 6.3 ③ 聊天详情（Chat）→ **主区（核心页）**

**目的**：与 agent 对话，看流式回复与工具执行，必要时审批。（同移动端。）

桌面端的差异来自两件事：**屏幕宽**（能同屏、能限宽）和**输入是键盘鼠标**（hover、快捷键、
正文不折行）。渲染规则本身**完全沿用**移动端 `interactions.md` §7.4（逐字追加、贴底跟随、
上滑暂停自动滚底、工具卡原地更新、思考默认折叠）。

**结构**：会话标题栏 + 消息流 + 底部输入区。

**1. 会话标题栏**（主区顶部，**不是**窗口标题栏）：

- 左：会话标题。hover 出现铅笔图标，点击**就地变输入框**重命名 → `PATCH /api/sessions/:id`。
- 副信息行：`Agent 徽章 · Workspace 名 · cwd（等宽、单行省略、hover 显示全文）· 权限模式徽章`。
- 右（actions，从左到右）：
  - **上下文占用圆环**——**规则全部沿用移动端 §6.3**：环上不写数字、点击弹 `16.6k / 258k · 6%`、
    只有占用没有窗口时退化成等宽小字 `23k`、**会话级**、切会话清空、**重连不重置**。
  - **运行状态 + 停止按钮**：`● 正在执行…` / `✓ 完成` / `✗ 失败` / `已取消`。
    移动端在消息流顶部另起一条横幅，桌面**并入标题栏**（省一行的垂直空间）。
  - **定时任务** ⏰：打开「任务」页并**只筛选本会话**的任务；页面顶部显示会话名和「查看全部」。
  - **会话设置** ⚙ → §6.9 的 ⑩。

**2. 消息流**：

- **正文容器 760 居中**——超宽屏上不要让一行文字横跨 2000px。代码块与工具卡**可突破容器宽**
  并横向滚动（宁可滚，不要折行破坏对齐）。
- 用户消息右对齐、`primary` 底；助手**不带气泡描边**，直接落在 `surface` 上（桌面宽屏下气泡框
  反而显乱），但保留 `surface` 与 `bg` 的层次差。
- **连续的工具调用折叠成一个「工具组」行**：移动端是一卡一工具；桌面上一个 run 常有十几到几十次
  调用，全铺开会把回复正文冲没。连续的 `tool_use`/`tool_result` 归成一组，折叠成一行
  `▸ 12 个工具调用 · Write, Bash, Read…`（hover 显示各状态计数），点击展开成原来的卡片列表。
  **正文文字之间**的组才断开——不按时间硬切。`⌘⇧E` 全部展开/折叠。
- **思考块**：默认折叠（沿用）；折叠行与工具组行**等高**，避免交替出现时行高参差。
- **hover 工具栏**：每条消息 hover 时右上角出现 `复制` / `复制为 Markdown`（🟡）；替代长按。
- **右键菜单**：复制 / 复制代码块 / 折叠该消息 / 跳到该 run 开头（🟡）。
- **滚动**：只在用户主动滚到底时恢复自动跟随；有新消息且未贴底时出现「跳到最新」（`↓`）浮标。
- ⚠️ **长会话必须部分虚拟化**（阈值 ~100 条）：**虚拟化历史、保留最近 N 条始终挂载**。
  原因是底部锚定的流式自动滚动会跟测量打架——把正在流式更新的那条也虚拟化掉，滚动条会逐帧跳。
  这不是可以事后补的优化：**从第一版就按这个结构写**，否则会话长了要重构渲染层。

**3. 底部输入区**：
- **输入框左下角**是一组下拉（新会话拿到 session id 后出现）：模型下拉 + 该模型目录声明的
  动态参数下拉（当前是「推理强度」，含「默认」+ provider 支持的值）。切换写入
  `sessions.model` / `sessions.model_parameters`，**从下一轮开始生效**；正在运行的任务不受影响。
  换模型时，新模型不支持的原参数自动回到默认。

- 多行 textarea，自动增高上限 **8 行**（移动端 6 行）。
- **`Enter` 发送 / `Shift+Enter` 换行**——桌面必须给这个约定；设置里可改成 `⌘Enter` 发送。
- 运行中：发送禁用、输入框上方 `任务正在运行…`；停止按钮在标题栏（见上）。
- 拖拽文件到输入区 → 插入其路径（🟡 桌面独有便利，后期）。
- 语音入口 🟡 后期（「按住 `⌘⇧S` 听写」，仍只填输入框不直接发送）。

**状态**：空闲 / 运行中（含流式）/ 完成 / 失败 / 取消 / 审批中 / 断线重连——**全部沿用移动端**。

另有一条必须覆盖的状态：**「这个会话的 run 是另一台设备发起的」**。表现与「自己发起」**完全
一致**（同一套流式渲染、同一个状态条、同样的审批），唯一区别是**输入框要禁用而不是可排队**
（不是我在跑，排了也没意义），并给一行说明「该会话正由其他设备驱动」。

这条**不靠推送**：**进入会话时**从 `GET /api/sessions/:id` 的 `runningRunId` 附着即可；左栏的
运行中标记来自常规轮询。桌面端**不订阅别的设备发起的 run 的内容**（技术方案已定 20）。

> ⚠️ 别把「输入框禁用」做成全局的：运行中的是**另一个会话**时，当前会话照常可以发。
> 禁用只针对「当前会话正在跑」。
> ⚠️ 发消息可能收到 **409 `session_busy`**（M0 上线的同会话守卫）——两个客户端同一瞬间发同一
> 会话时会撞上。按「该会话正在运行，已排队/请稍后」处理，不要当成通用错误。

**加载历史中**：居中转圈 +「正在加载对话…」，沿用；桌面可加骨架屏（更贴合桌面观感）。
渐进首屏（先用聚合 messages 渲染、再升级为事件级块）见技术方案 §3。
