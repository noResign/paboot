# ③ 聊天详情（Chat）— 桌面

> 索引与全局规范见 [../design.md](../design.md)。移动端原页：`docs/ui/mobile/pages/chat.md`
> ——**渲染规则与状态语义全部沿用，本文件只写桌面差异**。

### 6.3 ③ 聊天详情（Chat）→ **主区（核心页）**

**目的**：与 agent 对话，看流式回复与工具执行，必要时审批。（同移动端。）

桌面端的差异来自两件事：**屏幕宽**（能同屏、能限宽）和**输入是键盘鼠标**（hover、快捷键、
正文不折行）。渲染规则本身**完全沿用**移动端 `interactions.md` §7.4（逐字追加、贴底跟随、
上滑暂停自动滚底、工具卡原地更新、思考状态保留——桌面为一行，不画卡片）。

**结构**：会话标题栏 + 消息流 + 底部输入区。

**1. 会话标题栏**（主区顶部，**不是**窗口标题栏）：

- 左：会话标题（**单行省略**，hover 显示全文）。点击标题**就地变输入框**重命名 → `PATCH /api/sessions/:id`。
  会话尚未创建时标题是「新会话」、不可点：daemon 用第一条消息生成标题，此刻没有 id 可 PATCH。
- 副信息行：`Agent 徽章 · cwd（等宽、只取末 3 级、单行省略、hover 显示全文）· 权限模式`。
  权限模式本身是**按钮**：已有会话点它直接打开 ⑩ 会话权限——不再单占一个 ⚙；**尚未创建**的会话
  点它弹出三档菜单，改动作为创建参数随首条消息一起提交（只改显示会与首条 run 实际生效的模式不一致）。
- 右（actions，从左到右）：
  - **文件**：开关会话右栏（§6.8），打开时是按下态。右栏是**工作区级**的，新建会话还没发第一条
    消息时也能用。
  - **上下文占用圆环**——**规则全部沿用移动端 §6.3**：环上不写数字、点击弹 `16.6k / 258k · 6%`、
    只有占用没有窗口时退化成等宽小字 `513k tokens`、**会话级**、切会话清空、**重连不重置**。
    没有 run 就没有占用，**新建会话画一个空底圈**：与 0% 时的真实圆环同一副样子（同色同粗细、
    无进度弧），位置先占住，首条消息带着 usage 回来时标题栏不会跳动。
  - **运行状态胶囊**：`执行中` / `完成` / `失败` / `重连中` / `已断开`，圆点着色。
    移动端在消息流顶部另起一条横幅，桌面**并入标题栏**。停止按钮**不在标题栏**——见 §3。
  - **⋯ 更多**：重命名会话 / 会话权限（§6.9 ⑩）/ 记忆三档（正常 / 只记录不注入 /
    本会话关闭）/ 本会话的定时任务（打开带会话过滤的全局任务页，可「查看全部」）/ 收起会话列。
    记忆三档对 dev / life 会话都可用，工作区未启用时也能保存。定时任务和会话权限不再各占一个常驻图标。
    **会话尚未创建时**菜单形状不变，但这三项置灰并标注「需先发消息」（它们写 `sessions.*`，
    还没有那一行）；「重命名会话」此时不出现。

**2. 消息流**：

- **正文字符列 720 居中**（容器 760，左右各 20 gutter）——超宽屏上不要让一行文字横跨 2000px。
  底部输入卡片与这一列**同宽**（720），左右边缘对齐，不要出现「气泡比输入框窄」的错位。代码块与工具卡**可突破容器宽**
  并横向滚动（宁可滚，不要折行破坏对齐）。
- 用户消息右对齐、**品牌淡染底**（`primary-subtle` + 极淡同色描边），气泡下方右对齐显示
  发送时间（今天 `HH:mm`，更早带「昨天」/日期）；助手**不带气泡**，直接落在画布上（桌面宽屏下气泡框
  反而显乱），靠留白与排版分层。
- **连续的工具调用折叠成一个「工具组」行**：移动端是一卡一工具；桌面上一个 run 常有十几到几十次
  调用，全铺开会把回复正文冲没。连续的 `tool_use`/`tool_result` 归成一组，折叠成一行
  `▸ 12 个工具调用 · Write, Bash, Read…`（hover 显示各状态计数），点击展开成原来的卡片列表。
  **组头不画外框**：左侧 2px 线 + 30px 折叠行（hover 底色），组内工具卡仍是小卡。
  **正文文字之间**的组才断开——不按时间硬切。`⌘⇧E` 全部展开/折叠。
- **思考**：正文不下发。桌面不画卡片，只留一行 22px 状态——思考中显示「思考中」+ 三点动画，
  收到下一条内容事件后变回「思考」一行；不可展开。
- **不再在消息流里重复运行状态**：`正在执行…` 那一行已删除；标题栏胶囊 + 思考行 + 输入框各司其职，
  消息末尾只保留 usage / error。
- **hover 工具栏**：每条消息 hover 时右上角出现 `复制` / `复制为 Markdown`（🟡）；替代长按。
- **右键菜单**：复制 / 复制代码块 / 折叠该消息 / 跳到该 run 开头（🟡）。
- **滚动**：只在用户主动滚到底时恢复自动跟随。离开底部滚动时出现「跳到最新」（`↓`）浮标，
  **停止滚动 3 秒后自动隐藏**；浮标悬浮在输入框上边框之上，不遮挡输入区。
- ⚠️ **长会话必须部分虚拟化**（阈值 ~100 条）：**虚拟化历史、保留最近 N 条始终挂载**。
  原因是底部锚定的流式自动滚动会跟测量打架——把正在流式更新的那条也虚拟化掉，滚动条会逐帧跳。
  这不是可以事后补的优化：**从第一版就按这个结构写**，否则会话长了要重构渲染层。

**3. 底部输入区**：
- **输入框左下角**是一组下拉（会话页始终显示；新建会话、还没发第一条消息时也在）：模型下拉 +
  该模型目录声明的动态参数下拉（当前是「推理强度」，含「默认」+ provider 支持的值）。切换写入
  `sessions.model` / `sessions.model_parameters`，**从下一轮开始生效**；正在运行的任务不受影响。
  会话尚未创建时选择只留在本地，随首条消息的 `POST /api/chat` 在建会话时一并写入。
  换模型时，新模型不支持的原参数自动回到默认。

- **输入框左下角「+」**：选择图片，也支持直接粘贴 / 拖入；最多 8 张，png/jpeg/webp/gif，
  单张 ≤10MB。选图后先压缩（长边 ≤2048）并上传，缩略图显示在输入框上方，可单张移除，
  **点击缩略图看大图**。
  发送时图片与文字一起送给 AI；用户消息历史里也显示缩略图，点击看大图。
  当前模型不支持图片时「+」禁用并提示。
- 多行 textarea，**空态 2 行（44px）**，自动增高上限 **8 行**（移动端 6 行）；整个输入盒约 94px。
- **`Enter` 发送 / `Shift+Enter` 换行**——桌面必须给这个约定；设置里可改成 `⌘Enter` 发送。
- 运行中：输入框禁用、placeholder `任务正在运行…`、底部提示 `⌘. 停止运行`；不再有输入框上方的
  常驻提示（那句解释放进输入区 tooltip）。**发送按钮原位变成「停止」**（与移动端一致），点击即
  `POST /api/runs/:id/cancel`。
- **输入框上方的运行飘条**：显示**最早开始跑的那个 agent**的实时动作——`正在思考` /
  `正在调用工具 X` / `正在输出` / `正在回答`，随事件切换并轻微淡入；多 agent 并发时也只显示这一个，
  不罗列名字、不并列多个动作。点击进入「助手」页（被提问时文案变为「去回答」）。
- 拖拽文件到输入区 → 插入其路径（🟡 桌面独有便利，后期）。
- 语音入口 🟡 后期（「按住 `⌘⇧S` 听写」，仍只填输入框不直接发送）。

**状态**：空闲 / 运行中（含流式）/ 完成 / 失败 / 取消 / 审批中 / 断线重连——**全部沿用移动端**。

另有一条必须覆盖的状态：**「这个会话的 run 是另一台设备发起的」**。表现与「自己发起」**完全
一致**（同一套流式渲染、同一个状态条、同样的审批），唯一区别是**输入框要禁用而不是可排队**
（不是我在跑，排了也没意义），并给一行说明「该会话正由其他设备驱动」。

这条**不靠推送**：**进入会话时**从 `GET /api/sessions/:id` 的 `runningRunId` 附着即可；左栏的
运行中标记来自常规轮询。桌面端**不订阅别的设备发起的 run 的内容**（技术方案已定 20）。

> ⚠️ 别把「输入框禁用」做成全局的：运行中的是**另一个会话**时，当前会话照常可以发。
> 禁用只针对「当前会话正在跑」。
> ⚠️ 发消息可能收到 **409 `session_busy`**（M0 上线的同会话守卫）——两个客户端同一瞬间发同一
> 会话时会撞上。按「该会话正在运行，已排队/请稍后」处理，不要当成通用错误。

**加载历史中**：居中转圈 +「正在加载对话…」，沿用；桌面可加骨架屏（更贴合桌面观感）。
渐进首屏（先用聚合 messages 渲染、再升级为事件级块）见技术方案 §3。
