### 6.1 ① 连接服务器（Connection）

**目的**：让桌面端连上一台 daemon——**优先发现本机的**，其次连远程。

桌面端与移动端的根本差异在这里：手机永远连远端，所以它只有「填地址 + token」一条路；
桌面端**和 daemon 往往同机**，所以「发现本机」是主路径，手填是回退。

**关键元素**（居中卡片，宽 420，垂直居中；背景 `bg` + 极淡品牌渐变点缀）：

1. 产品 Logo + 名称 + slogan（沿用移动端）。
2. 🖥 **「本机 daemon」区块——桌面独有，且放在最上**。见下方四态。
3. 「── 或连接远程 ──」分隔线。
4. 服务器地址输入框（沿用：等宽、`http://` 前缀提示、缺 scheme 自动补）。
5. Token 输入框（沿用：掩码 + 眼睛切换 + 粘贴）。**桌面补充**：能自动读到 token 时预填并
   **显式标注来源**（见下）。
6. 名称输入框（可选，沿用移动端）：给这台电脑起可读名字，连接后切换器/设置页优先显示名称。
7. 主按钮「连接」（primary，全宽）。
8. 「最近连接」列表（沿用移动端全部规则：只记**连接成功过**的、同地址只留最新一条、最多 5 条、
   点击即填地址与名称）。
   - 桌面新增：远程条目若为 `http` 且非 loopback，右端一个 `warning` 徽章 **「未加密」**。
   - 展示规则同移动端：有名称时主行显示名称、副行显示**掩码地址**；未命名时直接显示掩码地址。
8. 底部小字安全提示（沿用）。

**「本机 daemon」区块的四种形态**（对应技术方案 §2 的候选表）：

| 发现结果 | 区块形态 |
|---|---|
| 探测到，且是本客户端托管的 | 「本机 daemon · v… · 路径」+「连接」；另给「停止」「查看日志」链接（→ §6.6） |
| 探测到，非本客户端托管（如 systemd） | 同上 + 灰字「由 systemd 管理」，**不提供停止/重启** |
| **没探测到** | ⚠️ 不能写成「未发现本机 daemon」——探测不出来只等于「候选表里没有」。必须列出**已试过哪些**，并把选择交回用户：<br>`○ 它跑在别的地址 → [填地址连接]`<br>`○ 确实没在跑 → [启动一个本机 daemon]`<br>`○ 我只连远程机器 → [填地址连接]` |
| 端口有响应但不是 paboot | 黄色警示「端口 4780 被其他程序占用」+「换个端口」；**不显示「启动」**，避免必然失败 |

**「启动一个本机 daemon」这一分支**（技术方案已定 23）：

1. **不再询问工作目录**：固定用内置 fallback `~/.paboot/defaultworkspace`（不存在会自动创建，
   daemon 按这个路径把它标记为内置）。Workspace 是 agent 的**写入边界**，但真实项目目录在进入
   App 后从「工作区」里添加，启动这一步不需要用户理解它。
2. 启动后**默认绑 `0.0.0.0`**（同一局域网可连），不再询问是否开放给手机；同时展示局域网
   地址 + token 的复制/二维码和明文 HTTP 提示（🔴 安全相关，见 §6.6）。

**token 的来源必须显式标注**（技术方案 §2 的 `tokenSource`）：能自动读到就写出
「已从 `~/.config/paboot.env` 读到 token」，**不要静默填充**——GUI 悄悄采集凭据是那种「能用但
让人不舒服」的设计。

⚠️ **本机是 `tokenSource='env'` 时不要读 `~/.paboot/token`**：那个文件只在「生成 token」时才写，
env 命中时它留着的是**上一次的旧值**，读了必然 401（本机就是这种情况）。

**交互**：
- 点「连接」→ 按钮 loading → 成功进入主界面（左栏 + 主区）；失败红字错误 + 保持输入。
- 应用启动时**先跑一遍发现**：命中就自动附着（省掉一次手动连接），没命中才停在本页。
  这与移动端的「冷启动跳过本页」是同一条思路，只是触发条件从「保存过连接」变成「发现了本机 daemon」。
- 扫码连接（移动端有）在桌面改成**粘贴连接串**（不做摄像头）；桌面更值得做的是**反向**——
  把本机 daemon 的地址+token 生成二维码给手机扫（§6.6）。

**状态**：
- 检测中（**点「连接本机 daemon」之后才发生**，不是打开页面就跑）：按钮 loading。
- 校验中：按钮 loading。
- 失败：区分「无法连接」「token 无效（401）」「端口被占用」「未加密」（§7 的安全警告）。
- 成功：持久化连接（远程 token 进 `safeStorage`；本机 daemon 的 token **不存**，见技术方案已定 15）。

### 启动策略与「连接本机 daemon」（2026-10 修订，§2 的落地）

**打开桌面端 = 恢复已保存的连接 + 探测一次 + 必要时自动启动本机 daemon。**

1. **上次选中的主机可用** → 直接进入 shell。工作区按 daemon 各自记忆（`serverId`），不会串到别的机器。
2. **上次是远程且不可达** → 停在连接页，保留这台主机的地址和错误；**不偷偷切到本机**（用户可能
   有重要会话在远程）。他可以用连接切换器或手动表单改连。
3. **上次是本机 / 没有记录** → 探测本机 daemon：
   - 发现 → 自动附着（loopback token 从 `<data-dir>/token` 读），不要求填地址/token；
   - 没发现且「启动应用时自动启动本机 daemon」开着（默认开）→ 自动 spawn（内置目录、端口
     4780–4789 自动挑、绑 `0.0.0.0`），成功后自动连接进入 shell。
4. **自动步骤失败**（token 来自环境变量、端口冲突、启动报错）→ 才落到连接页，显示原因；手动
   地址+token 表单和「启动本机 daemon」按钮保留为兜底。

| 结果 | 界面 |
|---|---|
| 候选表命中 | 直接附着并进入 shell；同时记入「已保存的连接」 |
| 命中但拿不到 token（`tokenSource=env`） | 附着地址预填，提示去 `~/.config/paboot.env` 取；明确写出「已从哪读到/没读到凭据」 |
| 端口被非 paboot 程序占用 | 提示「端口 4780 被其他程序占用」，不当作「没有 daemon」 |
| 没命中且自动启动关闭 | 落到三选一：`填地址连接` / `启动一个本机 daemon` / `我只连远程机器` |

远程连接不占首屏：进入 App 后用**连接切换器 →「添加电脑」**，或设置里的连接页。
「启动一个本机 daemon」按钮固定用内置目录，不再接目录选择器；host 固定绑 `0.0.0.0`（§2）。

> 空态文案沿用 §2 的写法：**「没找到本机 daemon（已试过：…）」而不是「没有 daemon」**——
> 我们只知道候选表里没有。这条铁律不变，变的只是**谁来按下按钮**。

**页面自上而下的顺序**（2026-10-10 修订）：手动表单（地址 + Token + 〔连接〕+ 最近连接）**在最上**，
本机 daemon 区块**在其下**。原先本机区块占着首位是错的：手动表单是**通用入口**（连远程、
连本机非默认端口都走它），本机 daemon 只是探测出来的**便利**。

**「没找到」时要写清**：本机没有 daemon **只影响「在这台电脑上跑 agent」**；连别的电脑上的
daemon 用上面的地址直接连，**不需要本机也起一个**。
