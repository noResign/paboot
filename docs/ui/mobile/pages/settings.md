### 6.6 ⑦ 设置（Settings）🟢

**目的**：查看/修改连接、默认偏好和工作区。

**分组**：
1. **连接**：服务器地址、token、重新连接。
   - token **只读展示且不暴露明文**：已配置显示掩码 `••••••••`，未配置显示「未配置」；修改 token 走 ① 连接页。
2. **工作区**：
   - 显示当前选中的 Workspace path；
   - 「管理工作区」按钮进入 **⑧ 工作区管理**；
   - 不在设置页内嵌工作区 CRUD。
3. **默认偏好**：
   - 默认 Agent（🟡 需模型列表）；
   - 新建 Session 默认权限模式：`ask` / `acceptEdits` / `bypass`。
     点击**立即选中**（乐观更新，不等接口）；`PATCH /api/config` 失败则弹回原选项并在下方显示失败原因。
     成功的刷新要**原地替换**，不要退回 Loading 态，否则整页会闪一下。
4. **通知**：后台任务提醒开关（默认开）。标题与开关单独一行，说明文案放在下方，未授权时以轻量文字入口引导系统设置。
   - 说明文案：任务完成、失败或需要审批时，若不在该会话页就弹系统通知（见 §7.7）；
   - 打开时若系统未授权，先请求 `POST_NOTIFICATIONS`（只弹一次），已拒过则提示"点这里去系统设置开启"；
   - **从系统设置返回时要刷新授权状态**（可能在那边开关了通知），不能只依赖开关初值。
5. **客户端更新**：只放「检查更新」按钮，不重复展示版本信息。
6. **关于**：App 版本（`BuildConfig.VERSION_NAME`）、daemon 版本（`GET /api/health` 的 `version`）。
   - 「关于」常驻显示；daemon 未连上时其版本显示「未知」。

**关键交互**：

- 修改默认权限模式 → `PATCH /api/config`（`defaultPermissionMode`）；
- 切换当前 Workspace → 更新客户端本地 `selectedWorkspaceId`，并通知 ② 会话、⑤ 文件刷新；
- 工作区增删改 → 进入 ⑧ 工作区管理。

### 6.6.1 ⑧ 工作区管理（Workspace Management）🟡 M2

**目的**：管理 daemon 上注册的工作区，选择当前工作区。

**关键元素**：
1. 顶栏：标题「工作区」+ 新增按钮。
2. 当前工作区卡片：高亮、显示 `check`。
3. 工作区列表：
   - 名称 + `path`（**主目录**）；
   - **附加目录**列表：每个目录一行（`＋ <绝对路径>`，等宽、单行省略）+「移除」按钮；
   - **路径展开**：主目录与附加目录的路径都是单行省略，**点该行**在它**上方**弹出一条完整路径的
     浮条（可换行、白底细描边），再点一次收起，点浮条本身也收起；两者共用一个展开态，
     所以同一时刻只有一条路径是展开的。
   - Session 数量；
   - 是否为默认工作区；
   - 是否启用；
   - 操作行：**固定四个按钮**（设为默认、启用/禁用、重命名、+ 附加目录），等分宽度、**不横向滚动**；
   - 删除：**左滑卡片露出「删除」并停在滑开位置**，再点它才弹确认框；点卡片本身收起滑开状态，
     列表滚动也收起，同一时刻只允许一张滑开。默认工作区的卡片不可滑（删除按钮不存在）。
4. 右上角「+ 新增」→ 打开 ⑨ 目录选择器（新增**工作区**）。
5. 「+ 附加目录」→ 打开 ⑨ 目录选择器（文案「选择附加目录」/「添加此文件夹」，
   且**不禁用**「已是工作区」，因为同一目录可以被工作区引用）。
6. 空态：引导新增工作区。

**规则**：
- 附加目录只有**一个来源**：在这里手动增删（早期还会在聊天里批准越界读取时自动写入，
  该机制已随读取门控移除）。本页是附加目录的**唯一管理入口**。
- 附加目录使该 Workspace **所有会话**（含以后新建的）都能读写该目录——UI 必须让用户看出
  这不是「只给当前对话」；
- 删除附加目录不删除磁盘内容，只是收回 agent 的可达范围；正在跑的 Run 下一次 spawn 才生效；
- 允许嵌套 Workspace（典型场景：daemon `--workspace` 指向根目录，再把其下的子目录注册为独立 Workspace）；
  仅拒绝**同一路径**重复注册；附加目录可等于另一个 Workspace 的主目录；
- **删除确认框**（从左滑露出的「删除」进入）：默认只删工作区（附加目录与书签随之级联清理，
  **磁盘上的目录和文件一律不动**）；该工作区有 Session 时必须显式勾选「同时删除该工作区下的 N 个
  会话」才能删——勾选后连聊天记录、运行事件、会话级授权一起删，但**电脑上的 Claude Code 会话记录
  不删**（同一目录重新加回来仍可续接）。有会话且未勾选时「删除」按钮禁用，避免必然失败的请求。
- **默认工作区不可删**：卡片不可左滑（因此没有删除入口），卡片底部补一行说明「默认工作区不能删除，
  需先把另一个工作区设为默认」。这条同时保证最后一个工作区删不掉（它必然是默认的），不会出现零工作区。
- 当前工作区被删除后客户端 fallback 到默认工作区（`WorkspaceSelection` 清空 → 落回 daemon 默认）。
- 删掉的工作区不会在 daemon 重启后自己回来：`--workspace` 只在**首次启动（工作区表为空）**时注册一次。

### 6.6.2 ⑨ 目录选择器（Directory Picker）🟡 M2

**目的**：从 daemon 所在电脑的文件系统中选择一个目录，注册为 Workspace。

**关键元素**：
1. 顶部：当前路径面包屑，可从任意层级点击回退。
2. 目录列表：只展示文件夹；可选显示隐藏目录；**已注册为 Workspace 的子目录标注「已是工作区」**。
3. 返回上一级。
4. 底部按钮「选择当前文件夹」。
   - 当前目录已是 Workspace 时按钮**禁用**并改为「已是工作区」，从源头避免 `workspace_exists` 报错。
5. 安全提示：`workspace 不是沙箱`；选择 `/`、`~` 等宽目录时二次确认。

**交互**：
- 默认从 `~` 开始；
- 点击文件夹进入下一层；
- 选择后调 `POST /api/workspaces`，成功后返回 ⑧ 并高亮新工作区；
- 失败时按 daemon 错误码给出中文提示（`workspace_exists` / `directory_not_found` 等，统一走 `util/ApiErrors.kt`）。

### 6.6.3 ⑩ 会话权限设置（Session Permissions）🟡 M2

**目的**：配置单个 Session 的权限模式和“允许全部”授权。

**关键元素**：
1. 顶栏：「权限设置」+ 关闭。
2. 当前模式：三档 Segmented Control / 单选卡片。**同一个保存值在不同 runtime 下语义不同，描述文案必须跟着
   会话的 runtime 切换**；未知 runtime 用中性文案，具体范围指回新建会话页：
   - `ask`：Claude＝「修改类操作询问」；Codex＝「工作区沙箱；不受信任的命令需要审批，工作区编辑可能自动执行」；
   - `acceptEdits`：Claude＝「编辑自动放行，Bash 仍询问」；Codex＝「工作区沙箱内的命令和编辑可自动执行；提权由 Codex 请求审批」；
   - `bypass`：Claude＝「全部通过（高风险）」；Codex＝「关闭沙箱并跳过工具审批（高风险）」。
   - 设置页里改的是**新会话默认值**，没有具体会话，所以固定用中性文案。
3. 已授权工具：
   - 列表：`toolName` + 授权时间 + 撤销按钮；
   - 底部「全部撤销」。
4. 说明文案：
   - 权限模式只对后续 Run 生效；
   - 撤销授权只影响后续请求，**不会撤回已经批准过的操作**；
   - Codex 的权限扩展在服务端可持续到当前轮结束，要立即收回只能停止运行。

**交互**：
- 切模式 → `PATCH /api/sessions/:id/permissions`；
- 撤销 → `DELETE /api/sessions/:id/permissions/grants/:toolName`；
- 成功之后刷新 UI；如果当前模式为 `bypass`，已授权工具显示为“已暂停”。
