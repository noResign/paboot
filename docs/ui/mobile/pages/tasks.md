# ⑪ 定时任务（移动端）

> 索引见 [../../README.md](../../README.md)；语义见
> [daemon/docs/scheduled-tasks.md](../../../../daemon/docs/scheduled-tasks.md)。

## 入口

- 底部 Tab 第 3 位：**会话 / 文件 / 任务 / 设置**。
- 页面顶部标题「任务」，副标题显示当前 Workspace 路径。
- 右下 FAB「+」进入 **AI 配置会话**（不再打开手工新建表单）。

## 列表

每个任务一张 Card：

- 名称 + 状态（未运行 / 运行中 / 成功 / 失败 / 会话忙 / 已错过 / 已停用）。
- `计划 label · 下次相对时间`（daemon 生成 `schedule.label`，客户端不拼 cron）。
- 目标：`执行命令` / `会话：<标题>` / `首次触发时创建会话`；AI 创建的任务追加「AI 创建」。
- 右侧启停开关（直接 PATCH `enabled`）。
- 点击进入详情 Sheet。
- 下拉刷新；页面重新可见时静默刷新；不做 SSE。

空态：说明「按计划自动唤醒会话，或在工作区里执行命令」。

## 详情 Sheet

- 名称、计划、目标、完全权限、来源（user / AI）。
- 下次 / 上次时间、执行次数、最近错误、停用原因。
- 操作：立即运行、启用/停用、**编辑**、删除（二次确认）。
  - 「立即运行」请求期间显示「启动中…」并禁用；`lastStatus == running` 时显示「运行中…」并禁用。
    运行期间详情每 5s 轮询一次，run 结束后按钮自动恢复。
- 正文：AI 任务的 prompt 或命令任务的命令（等宽字体）。
- 执行历史：最近 20 次 run（时间、状态、触发方式）；命令 run 的 stdout 直接以
  `RunDto.output` 内联展示。

## 编辑 Sheet

- 入口：详情页「编辑」。
- 名称、prompt/命令、计划（结构化预设）可改；类型不可改。
- **目标会话可改（仅 AI 任务）**：可切到当前 workspace 的另一个会话，或选「下次运行新建会话」。
  改绑从下一次触发开始生效，正在运行的 run 不受影响；切到新会话不会删除旧会话。`command` 任务不可改绑。
- 来自原始 cron 的任务没有预设元数据：只允许改名称和内容，计划保持原样。
- 修改（含目标会话）从下一次触发开始生效；正在运行的 run 不受影响。

## AI 配置流程（新建任务）

1. 点 FAB → 先弹确认框「用 AI 配置定时任务？」；用户点「开始配置」后才发请求。
2. `POST /api/scheduled-tasks/config-session`。daemon 打开/创建一个 **每 workspace 复用**的配置会话
   （标题「配置定时任务」），并起一条普通 run：第一句用户消息是可见的「定时任务配置模式」说明。
3. 客户端切到该会话；AI 先问**想完成什么任务/达到什么结果**，不向用户索要 prompt。
4. AI 根据目标起草执行 prompt，再确认：
   - 目标：已有会话（AI 调 `list_sessions` 让用户选）/ 首次触发新建；配置对话本身不作为执行目标；
   - 时间：每天 / 工作日 / 每周指定日 / 每 N 分钟 / 每 N 小时；
   - 把名称、目标、计划、**执行 prompt** 汇总，询问用户是否创建。
5. 用户明确确认后，AI 调用 `schedule_task`（带 `target`）。ask/acceptEdits 下还会再走一次 MCP 审批卡。
6. 创建成功后 AI 告知任务 id 和计划；任务列表刷新后出现新任务。
7. 配置会话留在会话列表；除非被删除或对应 runtime 不可用，否则不会每次新建。

## 错误与状态

- `schedule_invalid` / `task_limit_reached` / `session_busy` / `session_deleted` 等按
  `util/ApiErrors.kt` 映射为中文提示。
- 绑定会话被删 → 任务连带删除；回到任务列表刷新后该任务消失，不会出现点了才提示“会话已删除”的断链条目。
