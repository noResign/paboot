> 文档索引见 [../README.md](../../README.md)；Design Tokens 与组件库见 [../design-principles.md](../../shared/design-principles.md)。章节编号沿用拆分前的 `ui_design.md`，未重新编号。

### 6.3 ③ 聊天详情（Chat，核心页）🟢

**目的**：与 agent 对话，实时看流式回复、思考状态、工具执行、用量与结果。

**顶部栏**：
- 返回按钮。
- 标题（会话标题，🟢 点击可重命名 → `PATCH /api/sessions/:id`）。
- 副信息行：**runtime 名 · token 消耗**（上下文占用量）；**不显示会话目录**。
- **上下文占用指示**（在右侧 `actions` 区、「会话设置」左侧）：一个 18dp 的**进度圆环**。
  - 弧度 = 占用 / 窗口（12 点方向起顺时针）；底圈 `outlineVariant`，进度弧 `primary`。
  - **环上不写数字**——顶栏那一行要留给标题和 runtime，长文案会把它们挤掉。
  - **点击**弹出详情：`上下文 16.6k / 258k · 6%`（`DropdownMenu`，锚在图标上）。
  - 运行时不给窗口大小（Claude）时画不出比例，改用**等宽小字**显示占用量（`23k`）：
    空圆环会被读成「0%」，比不显示更糟。
  - 它是**会话级**状态：进入会话时由历史重建填回（不是等到下一次模型调用），切换会话清空，
    重连**不重置**（`?after=` 只回放缺口，重置就再也补不回来）。
  - 与消息末尾的用量条刻意是两个数：占用量会随上下文压缩**回落**，用量条只增不减。
- **模型入口**在右上角「会话设置」菜单里的一项：「模型：当前值 · 推理强度」——输入区只留
  `+` / 语音 / 发送，模型与推理强度并进会话设置。**会话页始终可用，包括还没发第一条消息、
  会话尚未创建的时候**：点开底部 Sheet 选择，先选模型（第一项「默认（沿用电脑端配置）」），
  再按目录声明的 `parameters` 动态渲染参数段（当前是「推理强度」，含「默认」+ provider 支持的值）。
  已有会话的切换写入 `sessions.model` / `sessions.model_parameters`，**从下一轮开始生效**；
  正在运行的那一轮不受影响。会话尚未创建时选择只留在本地，随首条消息的 `POST /api/chat`
  在建会话时一并写入。换模型时，新模型不支持的原参数自动回到默认。
- 同一个「会话设置」菜单里，**记忆 / 定时任务 / 权限设置三项在会话尚未创建时置灰**（它们要写
  `sessions.*`，没有 id 可写）；权限模式与模型不受此限——前者随首条消息一起提交，后者见上一条。
- 右上角「会话设置」菜单里新增「记忆」三档：正常 / 只记录不注入 / 本会话关闭，
  写入 `sessions.memory_mode`，对 dev / life 会话都可用；当前项打勾。
- 右上角「会话设置」菜单里新增「定时任务」：打开**本会话的定时任务**只读列表
  （名称 / 计划 / 状态 / 目标），底部可跳到「任务」页管理。没有任务时也可打开，提示去任务页新建。
  **不带图标、不加计数**，与其他菜单项保持一致；也不额外占用顶栏图标位。
- 右侧「会话设置」入口 → **⑩ 会话权限设置**，可修改权限模式、查看/撤销 grants。
- Workspace 徽章点击后显示当前会话所属 Workspace，但**修改当前 Session 的 cwd/Workspace 不支持原地切换**；需要“在新 Workspace 新建会话”。

**消息流**（核心，自上而下）：
1. **运行状态条**（会话运行中时显示）：由 `status` 事件驱动。
   - 进行中：`● 正在执行…`（对应 `label: "starting"`）。
   - 结束态：`✓ 完成`（`succeeded`）/ `✗ 失败`（`failed`）/ `已取消`（`cancelled`），带 `terminal` 标记。
2. 用户消息：右侧**主色淡底**气泡（主色混 surface，不用满色），宽度随内容增长；气泡下方右对齐
   显示发送时间（今天 `HH:mm`，更早带「昨天」/日期）。消息区域可用宽度小于 480dp 时最大占 85%，
   宽屏最大占 70%。
3. 助手回复块，按事件实时渲染；正文和工具气泡均左对齐，铺满消息区域可用宽度：
   - `thinking_start` → **思考卡片**（置灰、不可展开）。标题行的小转圈表示模型仍在工作；收到下一条
     内容事件（文本 / 工具 / 提问 / 终局）即停止转圈。思考正文不下发，卡片没有内容。
   - **等待首个事件**：run 仍 live、但当前回复还没有任何块（也还没收到 `thinking_start`）时，
     回复区先显示一个不依赖思考事件的「思考中」转圈；首个内容事件或 `thinking_start` 到达后由对应
     卡片接管。DeepSeek Harness 只在服务端回合提交后才发 thought，这个等待期必须有反馈。
     （输入框的停止按钮已经表示 run 在进行，不另外占用导航栏。）
   - `text_delta` → 助手文本（左侧 surface 气泡，与工具气泡一样铺满消息区域可用宽度，**逐字追加**）。
   - `tool_use` / `tool_result` → **工具卡片**（见 5.1，按 `tool_use_id` 更新同一张卡）。
     **相邻的多个工具调用折成一个工具组**（见 5.1.1）：折叠时只占一行摘要，展开后才是逐张卡片。
     断组点是真正插入的正文/思考卡片/提问，**不是计时器**。
   - `usage` → 消息末尾**用量条**：`↑ 1.2k ↓ 3.4k tokens · $0.18`（次文字，等宽）。Codex 显示当前轮所有模型调用的累计用量，续接时不计入历史轮次。
     注意与顶栏的**上下文占用**区分：用量条是「本 run 花了多少」（只增），顶栏是「现在窗口装了多少」（压缩后回落）。
   - `context_compacted` → 居中一行系统提示 `更早的对话已压缩 · 102k → 48k tokens`（builtin 自动压缩，
     只在本轮实时出现，不进会话历史）。
   - `question` → 问答卡片。每道题末尾有「其他」：选项都不合适时点开后输入自己的答案。
     **builtin 的事件带 `permissionId`**：run 正阻塞等待，所有题答完后由用户点「发送答案」确认
     （选完**不会**自动发，允许来回修改），答案通过权限决策端点回填为 tool_result、同一 run 继续；
     不带 `permissionId` 的（Claude 等）仍等本轮结束后把选择作为下一条消息发出。出现「其他」时
     同样必须点「发送答案」，避免边输入边提交。
   - 🔴 `permission_request` → **弹出权限审批浮层**（见 6.7，阻塞当前运行直至作答）。
   - `error` → error 卡片（error 色，显示 message）。
4. 出错时：error 卡片（error 色，显示 message）。
   - `error` 事件分**终态**（`terminal: true`，这一轮到此结束）和**非终态**（运行还在继续，
     只是过程中出了问题）。非终态的两个来源：运行时的传输层错误，以及 **agent 自己写到
     stderr 的问题行**（如 Codex 的网络/额度/沙箱失败）——后者是「运行中却毫无反应」时
     用户唯一能看到的线索，所以必须显示，而不是只留在 daemon 日志里。
   - 因此 error 卡片可能先出现、随后运行仍成功收尾（例如只是模型列表刷新失败）：
     **终态为 `succeeded` 时要清掉这条卡片**，别让一条好回答永远顶着红字。

**任务列表（TodoWrite）**（脱离消息流）：
- agent 通过 `TodoWrite` 声明的任务清单，**不混进消息流**，独立显示在**输入区上方**；点击标题行
  展开/收起，标题带 `已完成/总数` 计数。
- 🔴 **全部完成即隐藏**：整份列表都是 `completed` 时不再显示——否则它会作为一条永远说「已完成」的
  横条挂在输入区上方，成为历史噪音。**只留在飞的活**（有 `pending` / `in_progress`）。
- 状态字形：`completed` = ✓（置灰、划线）、`in_progress` = 运行中转圈（静止时 ●）、`pending` = ○。

**底部输入区**：
- **「+」图片入口**在输入框左侧：系统 Photo Picker 多选（≤8 张，png/jpeg/webp/gif，单张 ≤10MB），
  客户端先压缩到长边 ≤2048；缩略图显示在输入框上方，可单张移除。发送时与文字一起发出，
  历史用户气泡也显示缩略图，点击看大图。当前模型不支持图片时禁用「+」。
- 多行文本框（自动增高，上限约 6 行）。
- 🟢 **语音输入**：输入框**左侧**放麦克风按钮（`microphone`），按住说话、松开识别，交互见 7.6。
  客户端直连 DeepSeek ASR（需在「模型 Provider」页配置 API Key），识别结果**先填入输入框、由用户确认/编辑
  后再发送**，不直接发出——agent 指令需要精确，避免误识别直接执行。
- 发送按钮（`arrow_upward` 圆形，primary，输入为空时置灰禁用）。
- 运行中：发送禁用（输入可继续键入，供下一条排队），输入框上方提示"任务正在运行…"。
- 🟢 运行中提供「停止」按钮 → `POST /api/runs/:id/cancel`。

**交互**：
- 文本/工具结果支持长按复制。
- 工具卡片点击展开/收起 input+result。
- 工具组折叠时只显示一行摘要，点击展开/收起组内全部卡片（见 5.1.1）。
- 思考卡片不可点击；标题行转圈表示模型仍在工作，没有可展开的内容。
- 顶栏占用圆环点击 → 显示详细数值（`16.6k / 258k · 6%`）；无分母时显示 `23k tokens`。点空白处收起。

**状态**（务必覆盖）：
- 空闲、运行中（含流式）、完成、失败、取消、审批中、断线重连（见第 7 章）。
- **加载历史中**：进入已有会话要重建历史（按 run 逐个回放事件，会话越长越慢），加载期间消息区显示
  居中转圈 + 「正在加载对话…」，**不要留空白页**；加载完成或失败都要移除该指示（失败仍走错误提示）。
  > 根治方案（首屏只取最近 N 轮、向上滚动再加载更早）待实施。

**一条消息（assistant 回复）的可视化结构**：

```
┌──────────────────────────────────┐
│ ◌ 思考中                          │  ← thinking_start（不可展开）
│ 助手回复正文…（逐字）              │  ← text_delta
│ ▸ 12 个工具调用 · Write, Bash, …  │  ← 相邻 tool_use 折成一组（默认折叠）
│ ↑ 1.2k ↓ 3.4k tokens · $0.18      │  ← usage
└──────────────────────────────────┘
```

### 6.3.1 群聊与「助手」tab 🟡 目标规格（未实现）

> 当前 Android / iOS 仍是 `/api/chat` + per-run 流：在群聊会话里发消息只会由 leader 回答，
> 不订阅房间流，也没有 `@`。本节是移动端接入群聊时的目标形态；桌面端已按同一模型落地
> （见 `docs/ui/desktop/pages/chat.md` 与 `docs/local/multi_agent/07-client.md`）。

**触发**：会话成员 >1。用户 `@` 一个还没入房的工作区 agent 并发送时，daemon 先把它加入房间
再路由，会话就此升级为群聊（受「最多一个可写」约束）。单聊**不显示** tab 行。

**tab 行**：`对话` / `助手`（带成员数；有实时回答时显示小圆点，有待答问题时显示「需回答」）。

**对话 tab**：
- 只显示**已提交**消息；进行中的回答不在时间线里生长（在助手 tab 的进行区看）。
- 群聊消息带发言人（头像 + 名字），同一个 turn 只画一次用户提问。
- 召唤系统行：`── 补充：审阅、性能 ──`，由 leader 主答 `@` 触发。
- 时间线顺序 = **提交顺序**（`committedSeq`），不是发起顺序；重新进入会话按同一顺序重建。

**助手 tab**：
- **当前协作**（进行区）：实时卡片（固定两行预览、点击看该 run 的运行轨迹）、
  已派发/排队行（写清「排队中，等待当前回答结束」）、已就绪待显示行；
  **每一行有「停止」**（单任务取消），顶部状态条另给「停止全部」。
- **房间成员**：状态（正在回答 / 排队 / 已就绪 / 离线 / 已停用）、`重置上下文`、`移出`；
  底部「拉入已有助手」（工作区候选，不可用置灰）。
- 一个房间最多一个可写 agent；其他成员以只读身份加入。

**输入区**：
- `@` 候选来自**当前工作区**的 agent，未入房的标注「未加入」；点名即入房。
- 带 `@` 的消息暂不支持图片附件；纯图片消息仍走单聊路径。
- 发送 = `POST /api/sessions/:id/turns` → **202 + 任务列表**，不在响应体里返回答案；
  答案从房间流 `GET /api/sessions/:id/stream?after=<roomSeq>` 取。
- 原有「停止」按钮 = 停止所有任务；需要只停一个 agent 时用行内「停止」
  （`POST /api/tasks/:id/cancel`）。

**问题卡**：`AskUserQuestion` 的三种结算态分别显示——
`已发送答案` / `已回答拒绝；助手会自行处理` / `超时未回答；助手会自行处理`；
run 已结束的阻塞问题显示「这次提问已结束」，不可再点。

**契约现状**：DTO 已同步 `agentId` / `turnId` / `answerStatus` / `taskStatus` / `taskId`；
缺的是移动端的 `/turns`、房间流订阅和以上 UI。
