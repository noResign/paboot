# ③ 聊天详情（Chat，核心页）

> 文档索引见 [../README.md](../../README.md)；Design Tokens 与组件库见 [../design-principles.md](../../shared/design-principles.md)。章节编号沿用拆分前的 `ui_design.md`，未重新编号。

### 6.3 ③ 聊天详情（Chat，核心页）🟢

**目的**：与 agent 对话，实时看流式回复、思考过程、工具执行、用量与结果。

**顶部栏**：
- 返回按钮。
- 标题（会话标题，🟢 点击可重命名 → `PATCH /api/sessions/:id`）。
- 副信息行：Agent 徽章 · Workspace 名 · cwd · 权限模式徽章（可横向滚动/省略）。
- **上下文占用指示**（在右侧 `actions` 区、「会话设置」左侧）：一个 18dp 的**进度圆环**。
  - 弧度 = 占用 / 窗口（12 点方向起顺时针）；底圈 `outlineVariant`，进度弧 `primary`。
  - **环上不写数字**——顶栏那一行的宽度要留给 cwd，长文案会把 cwd 挤掉。
  - **点击**弹出详情：`上下文 16.6k / 258k · 6%`（`DropdownMenu`，锚在图标上）。
  - 运行时不给窗口大小（Claude）时画不出比例，改用**等宽小字**显示占用量（`23k`）：
    空圆环会被读成「0%」，比不显示更糟。
  - 它是**会话级**状态：进入会话时由历史重建填回（不是等到下一次模型调用），切换会话清空，
    重连**不重置**（`?after=` 只回放缺口，重置就再也补不回来）。
  - 与消息末尾的用量条刻意是两个数：占用量会随上下文压缩**回落**，用量条只增不减。
- **模型入口**在**输入框下方左侧**（不在顶栏）：一行紧凑的「模型 · 当前值 · 推理强度 ▾」，
  新会话拿到 session id 后才出现。默认配置用次要色，显式选过模型/参数时用主色。点开底部
  Sheet 选择：先选模型（第一项「默认（沿用电脑端配置）」），再按目录声明的 `parameters`
  动态渲染参数段（当前是「推理强度」，含「默认」+ provider 支持的值）。切换写入
  `sessions.model` / `sessions.model_parameters`，**从下一轮开始生效**；正在运行的那一轮不受影响。
  换模型时，新模型不支持的原参数自动回到默认。
- 右上角「会话设置」菜单里新增「定时任务」：打开**本会话的定时任务**只读列表
  （名称 / 计划 / 状态 / 目标），底部可跳到「任务」页管理。没有任务时也可打开，提示去任务页新建。
  **不带图标、不加计数**，与其他菜单项保持一致；也不额外占用顶栏图标位。
- 右侧「会话设置」入口 → **⑩ 会话权限设置**，可修改权限模式、查看/撤销 grants。
- Workspace 徽章点击后显示当前会话所属 Workspace，但**修改当前 Session 的 cwd/Workspace 不支持原地切换**；需要“在新 Workspace 新建会话”。

**消息流**（核心，自上而下）：
1. **运行状态条**（会话运行中时显示）：由 `status` 事件驱动。
   - 进行中：`● 正在执行…`（对应 `label: "starting"`）。
   - 结束态：`✓ 完成`（`succeeded`）/ `✗ 失败`（`failed`）/ `已取消`（`cancelled`），带 `terminal` 标记。
2. 用户消息：右侧主色气泡，宽度随内容增长；消息区域可用宽度小于 480dp 时最大占 85%，宽屏最大占 70%。
3. 助手回复块，按事件实时渲染；正文、工具和思考气泡均左对齐，铺满消息区域可用宽度：
   - `thinking_delta` → **思考块**（折叠，默认收起，点击展开，置灰等宽）。
   - `text_delta` → 助手文本（左侧 surface 气泡，与工具和思考气泡一样铺满消息区域可用宽度，**逐字追加**）。
   - `tool_use` / `tool_result` → **工具卡片**（见 5.1，按 `tool_use_id` 更新同一张卡）。
     **相邻的多个工具调用折成一个工具组**（见 5.1.1）：折叠时只占一行摘要，展开后才是逐张卡片。
     断组点是真正插入的正文/思考/提问，**不是计时器**。
   - `usage` → 消息末尾**用量条**：`↑ 1.2k ↓ 3.4k tokens · $0.18`（次文字，等宽）。Codex 显示当前轮所有模型调用的累计用量，续接时不计入历史轮次。
     注意与顶栏的**上下文占用**区分：用量条是「本 run 花了多少」（只增），顶栏是「现在窗口装了多少」（压缩后回落）。
   - 🔴 `permission_request` → **弹出权限审批浮层**（见 6.7，阻塞当前运行直至作答）。
   - `error` → error 卡片（error 色，显示 message）。
4. 出错时：error 卡片（error 色，显示 message）。
   - `error` 事件分**终态**（`terminal: true`，这一轮到此结束）和**非终态**（运行还在继续，
     只是过程中出了问题）。非终态的两个来源：运行时的传输层错误，以及 **agent 自己写到
     stderr 的问题行**（如 Codex 的网络/额度/沙箱失败）——后者是「运行中却毫无反应」时
     用户唯一能看到的线索，所以必须显示，而不是只留在 daemon 日志里。
   - 因此 error 卡片可能先出现、随后运行仍成功收尾（例如只是模型列表刷新失败）：
     **终态为 `succeeded` 时要清掉这条卡片**，别让一条好回答永远顶着红字。

**任务列表（TodoWrite）**（脱离消息流）：
- agent 通过 `TodoWrite` 声明的任务清单，**不混进消息流**，独立显示在**输入区上方**；点击标题行
  展开/收起，标题带 `已完成/总数` 计数。
- 🔴 **全部完成即隐藏**：整份列表都是 `completed` 时不再显示——否则它会作为一条永远说「已完成」的
  横条挂在输入区上方，成为历史噪音。**只留在飞的活**（有 `pending` / `in_progress`）。
- 状态字形：`completed` = ✓（置灰、划线）、`in_progress` = 运行中转圈（静止时 ●）、`pending` = ○。

**底部输入区**：
- 多行文本框（自动增高，上限约 6 行）。
- 🟡 **语音输入入口**（预留）：输入框**左侧**放麦克风按钮（`microphone`），交互见 7.6。语音转文字后
  **先填入输入框、由用户确认/编辑后再发送**，不直接发出——agent 指令需要精确，避免误识别直接执行。
- 发送按钮（`arrow_upward` 圆形，primary，输入为空时置灰禁用）。
- 运行中：发送禁用（输入可继续键入，供下一条排队），输入框上方提示"任务正在运行…"。
- 🟢 运行中提供「停止」按钮 → `POST /api/runs/:id/cancel`。

**交互**：
- 文本/工具结果支持长按复制。
- 工具卡片点击展开/收起 input+result。
- 工具组折叠时只显示一行摘要，点击展开/收起组内全部卡片（见 5.1.1）。
- 思考块点击展开/收起。
- 顶栏占用圆环点击 → 显示详细数值（`16.6k / 258k · 6%`）；无分母时显示 `23k tokens`。点空白处收起。

**状态**（务必覆盖）：
- 空闲、运行中（含流式）、完成、失败、取消、审批中、断线重连（见第 7 章）。
- **加载历史中**：进入已有会话要重建历史（按 run 逐个回放事件，会话越长越慢），加载期间消息区显示
  居中转圈 + 「正在加载对话…」，**不要留空白页**；加载完成或失败都要移除该指示（失败仍走错误提示）。
  > 根治方案（首屏只取最近 N 轮、向上滚动再加载更早）待实施。

**一条消息（assistant 回复）的可视化结构**：

```
┌──────────────────────────────────┐
│ ▸ 思考中（可展开）                 │  ← thinking_delta
│ 助手回复正文…（逐字）              │  ← text_delta
│ ▸ 12 个工具调用 · Write, Bash, …  │  ← 相邻 tool_use 折成一组（默认折叠）
│ ↑ 1.2k ↓ 3.4k tokens · $0.18      │  ← usage
└──────────────────────────────────┘
```
